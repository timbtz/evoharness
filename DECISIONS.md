# Deviations from the briefing (one line each)

- Cheap role model = `glm-4.5-air` ($0.2/$1.1 per 1M): cheapest z.ai model that reliably emits fenced code; strong = `glm-5.2`.
- Wiki knowledge: Mode A "inject" (index + top-2 pages by keyword overlap) is the default; Mode B "tool" (read_wiki, ≤2 reads) is implemented and selected via `Config.wiki_mode`.
- `Task` grew a `description` attribute (the prompt header) on top of the §3 protocol — every task needs it, the loop stays generic.
- Objective scalars: `quality_per_dollar` = (score − seed score)/max(usd, 0.01) at gate time; `time_capped` ≡ `quality` because the budget guard already enforces `max_seconds` for every run.
- Candidate ids are deterministic (`c0000` seed, `c{gen:04d}`, migrants `{id}m{t}`) so golden test 6 holds across processes.
- Binpacking private split: Zenodo 14162744 was inspected but rejected (capacity-150 / 250-item protocol mismatches our capacity-100 / 5000-item setup) → generated OOD instances instead (2× Weibull(1.5)·30, 2× uniform 20..70).
- PyVRP added as a ninth reference repo (user request): its Statistics/Result split maps to our ledger JSONL (write side) + `experiments/report.py` (read side, incl. CSV export à la `Statistics.to_csv`).
- GLM thinking mode disabled on every call (`thinking: {type: disabled}`): with it on, glm-5.2 spent 2.6k–16k+ completion tokens per call and sometimes never emitted content before the cap (parse errors at $0.07/call); with it off, the same prompt yields a clean code block in ~240 tokens. Evolution wants many cheap samples, not per-call deliberation.
- `parse_code` accepts a final unterminated ```python block (max_tokens truncation) — a syntactically broken tail just scores −inf in the sandbox; writer `max_tokens` raised 4096 → 16384.
- Fourth task `matmul_c` added (user request, 2026-07-18): C is now a first-class artifact language — `core/sandbox.run_c` compiles with fixed flags (gcc -O3 -march=native) and runs the binary in the same unshare/rlimit jail; `parse_code` + loop prompts made language-agnostic. Score = geometric-mean speedup vs the naive kernel timed in the same binary (cancels VPS load noise); correctness gated vs naive at 1e-7·n. Verified: seed 1.02×, hand ikj 11.9×.
- Fifth task `cvrp` (anytime CVRP, 2026-07-18): the evolved artifact is an entire module exporting `solve(coords, dist, demand, capacity, deadline, compile_c)`; scoring runs in a dedicated docker container (`tasks/cvrp/Dockerfile.eval`, `--network none --cpus 1 --cpuset-cpus 3 --memory 1g`) with automatic fallback to the unshare sandbox (`core/sandbox.run_python_docker` + `docker_image_ready`).
- cvrp scoring is HOST-side: the sandbox returns routes; `task.py` re-validates and re-prices them against its own distance matrices — a candidate printing forged JSON (or `os._exit`ing after it) scores -inf because no valid routes exist. Per-instance deadline enforced post-hoc (+1 s grace) with a harness-held `time.monotonic` reference; a non-returning solve is hard-killed by the sandbox timeout (n·budget + 15 s).
- cvrp task.py is 213 LOC (> the usual 150; the briefing pre-authorized ~250) and the seed lives in `tasks/cvrp/seed.py` (224 LOC, read as text) — inlining a 200-line seed string would have blown task.py past 400.
- cvrp A/B/P instances are fetched from the galgos CVRPLIB mirror by numeric id (the relaunched site has no name-based URLs; ids pinned in fetch.py), X instances from PyVRP/Instances by name.
- cvrp adversarial-review fixes (opus subagent): `run_harness` hardened against non-dict/malformed payloads (all tasks benefit); cvrp solutions matched positionally with instance NAMES withheld from the sandbox (denies memorized-BKS lookup keys); host-side route-length bound + empty-route filter; `compile_c` temp dirs cleaned up; docker runner gained `--cap-drop ALL`, `no-new-privileges`, `--memory-swap` cap and a wedged-daemon kill path. Accepted residuals: instances remain fingerprintable by coords/n; per-instance +1 s grace can stack but total wall is capped host-side at sum(budgets)+8 s; sandbox stdout is unbounded (PoC threat model, pre-existing for all tasks).
- cvrp new render kind "routes" (multi-polyline) added to web/index.html — the existing "tour" renderer draws a single closed tour and cannot show multiple depot-anchored routes.
- Docker: single `api` service (runs execute as threads inside the API process — a separate worker service would duplicate state for no isolation gain at this scale); inside containers without user namespaces the sandbox auto-falls back from `unshare -rn` to the socket-stub preamble.
- Compile repair is mandatory baseline, not a sixth axis (user decision, 2026-07-20): a candidate whose error is a C-toolchain failure (`compile failed` from cvrp's `compile_c`, or raw gcc `.c:…error:` diagnostics from `run_c`) is repaired in-conversation — the same writer gets the compiler stderr as an immediate follow-up turn, up to `COMPILE_REPAIRS = 2` extra calls per generation (`core/loop.py`). Failed attempts are still ledgered as rejected candidates (`c0007`, then `c0007r1`, `c0007r2`); the last attempt becomes the generation's candidate. Rationale: "it compiles" is a floor every optimizer variant should share, so leaving it as a switch would confound the 5-axis screening; runtime/validation errors remain ordinary next-generation feedback (only the LAST candidate's error enters the next prompt, capped at 800 chars — errors never accumulate).
- Run continuation (user request, 2026-07-20): `Config.resume_from = <run_id>` seeds c0000 with that run's best accepted candidate (scanned from its ledger, train-score max, latest on ties; fallback `best.py`) instead of `task.seed_code()`. Task must match the resumed run's; validated fail-fast in `POST /api/runs` (422) so a bad request never creates a dead run dir. Frontend: "⟳ continue" button on done runs in the past-runs strip — starts a new run with the current panel config + `resume_from`, task forced to the resumed run's. A continuation is a NEW run (own dir/ledger/budget) referencing its ancestor via config + c0000 meta, keeping ledgers append-only and single-run.
- Plateau fixes (run-analysis 2026-07-20, binpacking-s0-41921694 / -41655420): (a) gates accept exact score TIES when novelty > 0 (lateral drift across plateaus — most binpacking mutations are argmax-equivalent to their parent and previously froze the search); (b) Greedy11 and Islands rank equal scores by newest gen so accepted ties actually become the incumbent; (c) Islands seeds the root candidate as island "all" (bugfix: it was pinned to island 0, leaving islands 2-3 empty → IndexError in rng.choices every visit, half of all generations skipped) and never prunes it; prune keeps newest-per-unique-score.
- Reflections learn from REJECTED candidates too (they carry all the signal under strict gates; previously reflections required >= 2 accepted candidates and never fired in runs where nothing was accepted — 0 reflect calls in 32). Identical (worse, better) pairs reuse the cached reflection instead of re-billing two calls per generation.
- Tie feedback: when a candidate scores exactly its parent's score, the next prompt says so explicitly (order-preserving decoration, no decision changed) — cheapest and most actionable signal the harness can emit.
- Binpacking wiki: heuristic-families.md now leads with the ordering rule (argmax invariance: monotone transforms ARE best-fit; a term must have slope > ~1 per unit gap, or a discrete jump > 1, to flip any placement) and the composition template uses magnitudes that actually reorder — the old template was bit-identical to best-fit and funneled writers into a score-neutral equivalence class.
- CVRP splits restructured (train saturation, run cvrp-s1-40028152): seed hit gap 0.0 on all five small A/B/P train instances → gate signal saturated at the max. Now train = X-n101/110/125 @5s, val = X-n153 @5s, private = X-n200/251/303 @6s; the small A/B/P set (still optimal for the seed in <3s) is the public progress-report split.
- Staged search (user design, 2026-07-20, third `search` option): stagnation-driven pipeline — climb the incumbent; after 50 generations without a new GLOBAL best, demand a full redesign and ADOPT it as the new branch root even if it scores worse (it gets its own 50-gen budget); operator directives (simplify/combine/wildcard) rotate in every 25 barren generations. Loop hooks: search may expose prompt_sections() (directive injection) and adopt(cand) (gate bypass, tried before the gate). Branch ids in cand.meta; pool.best() ignores branches so the run's result is always the global best (elitism). Not part of the 2-option screening grid; screening keeps greedy|islands.
- Live user steering: a run_dir/HINT file's text is injected each generation as a "Directive from the user" prompt section (edit/delete anytime, like STOP). Applies to every config.
- Per-instance feedback: parent and rejected-attempt sections now carry gaps_pct when the task reports it (cvrp); plain worse-and-rejected attempts get an explicit rejection note (previously silent).
- Noise-aware gating: tasks may declare `noise = {split: eps}`; gates re-evaluate a candidate whose margin vs parent is within eps (median of 3) before deciding. cvrp: train 0.02, val 0.05 gap-pct pts (measured: same-code private evals varied 0.628% vs 0.704%).
- Reasoning tracing (user decision, 2026-07-22): `llm_call` events now carry the full response `text`; every candidate records the writer's `Idea:` line (`meta.idea`, contract added to SYSTEM + trailing instruction) and its prose preamble (`meta.reasoning`, code fences excluded); Reflections logs a `reflection` event (pair, short, long) whenever a new pair fires. Rationale: run analysis of cvrp-s3 was only possible via code diffs — "why" was unrecoverable (parse_code discarded the preamble; reflections lived only in memory). JSONL, so no migration; report.py/web ignore unknown fields/types.
- Memory wiki (user design, 2026-07-22, third `feedback` option "memory", axes/memory.py): run-scoped Karpathy-LLM-wiki at run_dir/memory — index.md as the library (one line per page), SCHEMA.md as the maintainer instructions, four ShinkaEvolve-scratchpad section folders (successful-patterns / ineffective-approaches / implementation-insights / performance-analysis), one file per distinct pattern. Writers READ ONLY: index injected each generation + read_memory/grep_memory tools (loop now merges tools from knowledge AND feedback axes). A separate reviewer agent (feedback model, temp reflect, role "reviewer") maintains the wiki: fires every 20 candidates since last review OR on a new global best, sees only the unreviewed stretch (cap 50: id, accepted, score, error, novelty, idea, reasoning), rewrites pages via `=== FILE: path ===` blocks (path-validated to the four sections + index.md), ledgered as `memory_review`. resume_from copies the ancestor run's memory dir — cross-run memory accumulates. Not in the screening grid; precedents: ShinkaEvolve summarizer, KernelEvolve filesystem KB (arXiv 2512.23236), Karpathy llm-wiki, GEPA (reflective verbal learning beats scalar-only signals).
- Memory wiki correction (user decision, 2026-07-22, same day): NOT per-run — ONE shared wiki per task at `<repo>/memory/<task>/` (e.g. memory/cvrp/); every feedback=memory run reads and extends the same memory, resume-copying removed. Per-run traceability stays in the ledger (memory_review events; the reviewer's full output is in llm_call.text). SCHEMA.md now mandates conservatism: strengthen existing pages ("tried N times / variants — score-neutral") instead of adding prose when a stretch merely re-tried known approaches; record HOW an approach was implemented, not attempt narratives; an update touching nothing but index.md is a valid review. Known accepted residual: two concurrent runs on the same task can interleave reviews (last-writer-wins per file) — fine at PoC scale.
- Memory reviewer v2 (user decision, 2026-07-22, after cvrp-s3-45465035 A/B — private gap 0.581% vs score_only's 0.748%): SCHEMA.md now enforces a COVERAGE rule (every distinct approach in the reviewed stretch appears exactly once — own page or labeled bullet; parse/compile-dead ideas go to new-ideas/, never dropped) with a mandatory markdown page format (# title / claim / ## How it was tried, bullet per variant with ids / ## Why it worked-failed grounded in code / ## Verdict), replacing the earlier be-conservative wording that produced lossy 200-1000-token reviews. Reviewer digests now include each candidate's CODE (full, or unified diff vs parent when >4k chars, capped 6k) — judging attempts by the writer's self-description misclassified c0027 (kernel-identical overlay labeled "algorithmic replacement"), and the injected error redirected ~1/3 of the run's candidates into a refuted direction; reasoning cap raised 700→2000 chars, reviewer max_tokens 8192→32768. Sixth wiki section new-ideas/ added (SECTIONS + path validation + scaffold). memory/cvrp enriched from the run's full traced ledger and merged with the pre-tracing evidence. Known open items: parse_error generations still charge the slot without retry; eval-noise-aware gate margins may need widening (semantic no-op c0017 spanned 0.09 train / 0.14 val).
